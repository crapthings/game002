## 01-A：日程与住处

基于 `69ce01c`。新增 `gameplay/life.js`、`living/dailySchedule.js`；接入 runtime、类型、容量提示、场景与存档现有事务。

七人的原工作/住宅地址保留；其余五人的住址从现有住宅中按稳定规则选取，并复用跨区道路、地形、建筑碰撞确认。住宅不足时使用明确标记的临时歇脚处；没有合适位置则显示阻塞原因，不传送或覆盖已保存位置。新住址只加入 gameplay.places，不改旧布局或旧配置签名。

`places.extend + life.initialize` 在同一个请求与检查点里保存；旧世界不会只保存了一半住宅。需求初值为精力 100、饥饿 10，绑定角色 ID；随后到达的新身体必须有住处才能接入生活域。

活动选择只读取统一日历、绑定和本人状态。七人按任务 01-A 的白天/夜间日程选择工作、回家、巡逻、逛街；每人每模拟秒重新考虑，活动没变不写事件。进入新活动先行走，只有实际到达并取得接触证据才记为在场。旅行轨迹是可丢弃缓存，意图和需求随 gameplay 原子保存。

原战斗、追捕、举报、移交和回礼先于普通日程。01-B 继续补这些优先行动对休息计时的显式中断与恢复。正常值班表覆盖昼夜；死亡或案件导致的缺岗由后续职责/代班处理，不凭远处角色的全局健康值编造交班消息。

源码审阅覆盖：新字段通过显式增量日志加入；旧 v1 冻结文件未修改；同一活动不重复写入；实际到达才开始休息；保存等待不推进时钟；旧住宅和钱物不重置。未运行跨 08:00/18:00、往返住处、读档与碰撞验收。

## 01-B：需求、中断与恢复

01-A 提交 `db25cf5`。需求用模拟时间投影：每游戏小时饥饿 +8；实际进入休息点且没有中断时精力 +12，其余 -4；范围 0—100。活动切换/到达/中断时结算到同一模拟时刻。

精力 ≤25 发起优先休息，到 ≥65 才结束；饥饿 ≥60 寻找食物，到 <40 才结束。自有干粮带回住处吃，没有干粮去公开药铺；04-A 才允许通过真实库存消费减少饥饿。本卡不凭到达恢复饱食，也不饥饿扣血。角色每秒按稳定偏移重新考虑，避免一帧全部改行；原活动 ID 与优先级不变时不写新事件。

近身危险/战斗、追捕/逃险、举报/移交、回礼分别以 90/80/70/60 优先于日常活动。已经见到近处攻击者的居民先躲避再报案；不在挥击中移动以求援。中断保存原意图 ID 和原因，并释放可重建的路线缓存，不删除举报证据、物品、回礼时间或案件。安全后若日程未变则恢复同一意图；时段或需求已变则重新选择目标，抵达前不累计休息收益。

源码审阅覆盖中断幂等、优先级提升、恢复前实际行动分支、独立的路线取消及旧事件链保留。未运行追逐/逃离后恢复、连续读档、夜间缺粮与长期数值验收。

## 02-B：营业和交易限制

01-B 提交 `52f3a6b`。新增 `gameplay/commerce.js` 与 `living/serviceMessages.js`。场所服务规则通过 `places.enable_services` 显式日志启用，不改变此前 v2 请求的恢复语义。

场景即时检查 2 米、朝向、遮挡和经营者是否真在铺面；runtime 对启用后的买卖再次检查同一模拟时刻的营业时间、在场记录、正在工作、生命/战斗状态、本人已知的拒绝理由和现场证据。物品、价格、钱包及容量仍由原交易 reducer 原子校验。私宅门口不新增虚构的非法入侵事件。

到 08:00 但尚在路上的掌柜不能营业；18:00 后打烊；举报/逃险/休息时中断服务；死亡显示无人经营。场所状态按每秒检查且只记变化，闭店不删除或补齐库存。UI 买卖按钮与规则共用可用性结果，并给出营业、距离、库存/钱袋原因。

源码审阅覆盖旧记录启用边界、现场条件更新、死亡/离岗与库存保留、原匿名知识限制。远处是否关门的实际原因尚未直接向玩家展示，由 10-A 限定可见依据。未运行关门边界、打开面板后离开、交易时受击及旧 v2 增量恢复验收。
