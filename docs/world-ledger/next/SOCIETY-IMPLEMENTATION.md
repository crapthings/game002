## 03-A：同一关系表上的有向态度

新增 `gameplay/relations.js` 和冻结初始联系配置。通过显式 `relations.initialize` 填充邻里、亲属、同僚的两条有向边；原 trust 保留，fear/gratitude 缺失时置0，不重置旧柳娘恩情。态度值仍唯一存在 `social.relationships`，relations 只记初始化、应用证据和变化事件。

`relationFor` 统一查询；`relationReaction` 只接受本人确实有记录、且认出当事人的证据。亲自受助与听到邻里受助的变化不同；未认出蒙面者不生成指向真实玩家的好感。每人每事实只应用一次。旧 aid 已经产生的 trust 不再次累加，只补新字段；履约现场的委托人可以获得完成证据。

闲置 NPC 接活同时参考自己对委托人的信任、畏惧和恩情；有足够信任/恩情时可明确无偿承接，不把无偿变成未支付的报酬。受伤害而畏惧的平民，在认出近处玩家时先保持距离；捕快职责与既有自卫/判责优先。历史推导在提交后的状态索引里缓存，不每帧重新查所有关系反应。

源码审阅覆盖旧 trust 单一来源、匿名边界、双向不对称、事实去重、行为接入和领域公开契约。未运行 NPC 接受/避让、旧救助恢复、UI 可读性和反复转述验收。下一卡 03-B 接真正会面后的有限传播。

## 03-B：当面、有来源的有限传播

03-A 提交 `d54af37`。新增 `knowledgeLineage`、`exchange`、`socialController`；会面条件提取到共享 `meeting.js`，保持先前的距离/朝向/状态语义。通过显式启用事务添加传播规则，旧 dialogue 新闻命令在未启用前仍走原处理路径。

NPC 在真正 2 米接触且确认无遮挡时向熟人转述自己知道的事实；选题读本人的亲历与关系，不读对方私有知识决定“他缺哪条消息”。接收方如果已经知道，在现场表示知晓，记录这次交流但不刷知识或关系。只有确实收到的新内容才走原 report 证据链；本人/来源人、原证据、接收时间、匿名程度和跳数均可追溯。

原目击为0跳，普通传话最多两跳。一次双方会面最多交流一条，每个发信 NPC 至少间隔60模拟秒；离开3米后结束已记录会面，保存恢复不会凭空开启另一场谈话。正常询问新闻也使用这套规则；紧急报案继续走已有真实证据链，不通过普通闲谈提高案件严重度。

已知救助可在柳娘与石伯真实相遇时传过去，再由石伯自己的关系反应产生信任/帮助倾向。未知蒙面恩人不会因亲友传话恢复成真实玩家 ID。玩家可当面问“你怎么看我”，回答依据说话者自己的态度和是否认出当前来人。

源码审阅覆盖证据深度、陌生身份不升级、重复交流/读档限频、已知事实回应、同一事务落盘、仅按需派生索引和对话旧版本路径。尚未运行柳娘→石伯的城内相遇、两跳边界、离开/返回和连续运行验收。没有声称角色已经在实际画面中完成这条链。

## 04-A：吃饭与有限补货

03-B 提交 `c6d6a40`。新增 `economy`、`procurement` 和场景消费控制器；供应商仍用12-A冻结的 supplier-1 模板，100文、40药、80干粮，复用货郎模型。城门由实际 fortifications.gates 选定，卸货场先作为候选，再确认坡度、碰撞与接入道路后通过 registry 原子登记人物/钱物/场所/身体。找不到安全地点时保留原因，不以原点替代、不重复出生或重置库存。

居民饥饿达到60时去买一份真实干粮，再带回可用地点吃下；已经持有的自有干粮可以直接消耗。进食单独减少60饥饿，满血仍可吃，不调用“治疗满血失败”的旧 use 分支。本人缺钱、店里缺货或无法服务留下需求，暂不因饥饿扣血。掌柜与货郎吃掉的也是自己现有的干粮。

药铺目标库存4药/6干粮，实际交易、进食或上一批入库形成新的短缺来源。相同库存需求不因终态/下一帧重新生成，一次只保留一批活跃采购，观察短缺至少间隔60模拟秒。04-B 的缺货生成部分随这一条真实采购路径提前接入，工资仍在下一卡。

采购生命周期仍在 opportunities，没有第二套订单完成状态。接受时分别约束采购款和跑腿报酬；批发价9/3文，零售价15/5文。新增跑腿报酬固定2文，来自掌柜钱包；愿意无偿跑腿也必须有真实采购款。承运人到卸货场与货郎实际会面，先核对有限源批次，在同一事务预留/转交实物并支付批发款；货物从此归掌柜所有、由承运人实际持有。原货物预留可表示这个所有/保管分离，不会免疫抢夺。

到药铺当面交回才入库存，跑腿报酬一次结清；欠付时货物已入库、报酬仍保留。背包不足时整笔取货回滚，没有先扣部分采购款。缺货或采购款受损时当场记失败；货已取走后丢失/死亡/取消/过期，保留原所有权和货物返还责任，不能生成第二份。原承运人可以把仍持有的原批次交还物主，原委托不复活、不再次领奖。

NPC 可看见铺前掌柜招呼帮手，靠近后才正式获知采购内容；闲人仍按同一委托接口接单、沿道路取货和回程。玩家对话可接单/取货/交货/归还，任务面板显示采购目的地；货郎的远处库存不会成为地图实时数据。

源码审阅覆盖新人物原子到达、源批次有限/不跨日补出、满血吃饭、采购款/报酬唯一来源、携带者所有权分离、容量失败回滚、取货/交付去重、货损/死亡、旧消息任务兼容和缺货去重。尚未运行货郎落位、整条采购路线、连点/旧档/丢货、供货耗尽和 UI 验收；不宣称实际运输已经完成或数量测试通过。

## 04-B：实际工时、工资和欠付

04-A 提交 `7282b5a`。通过显式 `enable_employment` 登记小何替陈掌柜搬运的初始约定；工作地点使用小何原有的中心商区绑定，避免把已告知的带话地址改错。任何一方已经死亡时不生成新的有效雇佣，不改旧人物身体或钱包。

`employment.js` 的工时只累计实际工作阶段：本人位于工作点、已经抵达、双方活着、本人没有其他中断且不在交手；离岗或与玩家交谈暂停。到岗、暂停、跨整小时才写记录；一小时按60000模拟毫秒，零碎工时累积保留。领域事务中的战斗/日程打断或死亡在同一笔操作里截断原工作区间，不等下一帧再补记。

每累计完整一小时获得2文应付工资；付款使用陈掌柜的同一个可支配钱包，逐个稳定小时序号支付。一次小时工资全付或不付，不把已付的小时再次计算。缺钱记录欠付，后来有可支配资金再按最早未付小时结清；不会给活人或尸体另生一份钱包。双方死亡后的未付记录保留给后续善后，不自动发钱或复活。

小何在当面对话中可以说明自己的工作地点、时薪和尚待结算的小时数。购买/补货与工资竞争同一可支配资金；采购约束不会被工资绕过。短缺模板继续按04-A的真实库存来源和新需求版本生成，现有活跃采购与同一终态原因不重复下单。

源码审阅覆盖部分小时保留、保存/菜单暂停、交谈与战斗中断、死亡边界、同一钱包预留、逐小时去重和欠付补发。未运行跨小时/跨保存、雇主缺款、攻击中断及持续营业验收；下一卡12-B必须接真正的归档事务，现有4096容量保护保持有效，未宣称长时间运行已经可用。
