# P0：让七名角色进入城内各自的地方

优先于十二项扩展。保持现有七名角色和道具目录，用现有建筑和街巷组成第一条城内游玩路线。本文件中的安排尚未实施。共享约定见 [CONTRACTS](CONTRACTS.md)。

## 位置与功能

| 角色 ID | 人物 | 场所绑定 | 首版活动 |
| --- | --- | --- | --- |
| merchant | 陈掌柜 | `place.medicine`，百业集市街附近的药铺或合适摊位 | 门前营业，药包在旁边可达的位置 |
| witness | 阿青 | `place.market-neighbor` | 集市附近短距离走动和驻足，保留真实目击条件 |
| guard | 周平 | `place.yamen-desk`，府衙外接案点 | 值守、接案、追捕、送回药包，办完返回 |
| guard-2 | 林岳 | `place.yamen-patrol` | 衙前—主街—中心商区巡逻，紧急事务可中断 |
| resident-1 | 柳娘 | `place.home-liu`，实际住宅门前 | 受伤等待救助，恢复后按已有条件答谢 |
| resident-2 | 石伯 | `place.home-shi`，另一住宅门前 | 邻里线索；后续由 06-A/07-A 接入找小何委托 |
| resident-3 | 小何 | `place.central-contact`，中心商区街侧 | 在商区活动，后续作为找人目标 |

地图现有坐标：百业集市街 `(0,-64)`、中心商区 `(48,0)`、清平府衙 `(16,112)`。这些坐标用于寻找附近场所；不能直接作为所有人物落点。城内有 `z=26..38` 的河道，跨河沿已有五座桥通过。

P0 复用两条已实现事件链：集市取药包→目击者走到捕快→案件→交还→捕快实际送回；居民区见柳娘→去集市买药→回来救助→以后当面答谢。第三条“石伯找小何”在通用委托和对话接口到位后接入，P0 不另写一套临时背包、奖励或任务计数。

## P0-01：只建立地点和人物绑定

依赖：基线同步。适合单独交给低思考强度执行；本卡不启用位置迁移。

改动：新增 `src/game/living/cityPlaces.js` 和 `cityRoles.js`（规划路径）；读取 `world.city.placements/parcels/roads/landmarks` 及 `src/game/assets/wuxia/catalog.js`。旧 `firstLoop.js`、NPC/物品配置和世界生成器保持原规则。

拟公开 `resolveCityPlaces(plan)`、`createCityRoleBindings(places)`，输出共享约定中的 PlaceDefinition 和 ActorBinding。解析只产生候选，不能声称候选已通过运行时碰撞。

具体步骤：

1. 按 asset kind、parcel 用途和到地标的距离给候选排序；同分按 placement.id，保证同一世界结果一致。优先药铺；集市没有药铺时选现有摊位并明确绑定为陈掌柜摊位，不改原模型。
2. 住宅依据资产 home 标签及真实 placement 选择；柳娘与石伯使用不同住宅，优先靠近可连通街巷。衙门选择 government 建筑外广场。排除河道、桥中、墙体和主街中心。
3. 根据实际建筑朝向、占地及接入巷道计算街侧 approach，入口前保留交互空间。相邻生活目标以实际路程约 40—80 米作为选址目标，允许现有道路要求的合理绕行。
4. 输出缺失候选及原因；少数种子没有合适建筑时使用该功能区内已存在的公共空地候选，并在结果中记 `fallback`。无安全候选时返回未解析状态，不能悄悄使用中心 `(0,0)`。

完成标准：七个 actorId 各有一个有效绑定；两个住处分开；出处能追到建筑/地块；重复解析不换位置。交付选址清单与人工核对案例，不运行仓库禁止的验证命令。

## P0-02：跨街区导航与独立的碰撞数据

依赖：P0-01。集中审阅点：流送/导航数据生命周期。拆成“纯道路图→导航数据缓存→场景适配”三个连续小提交，每次只实施一个部分。

涉及：`living/navigation.worker.js`、`createNavigationWorker.js`、`geometry.js`、`world/chunks/createStreamedWorld.js`、`movementQuery.js`、`collisionIndex.js`；拟新增 `living/cityRouteGraph.js` 和 `world/chunks/navigationResidency.js`。

具体步骤：

1. 从已有 city.roads 生成道路图，分割交点，加入桥两端连接和场所 approach。全局路径输出道路航点，再将局部目标拆到约 12 米内交给现有 Worker 绕障。保留局部搜索预算，不把 1,800 直接改成无限搜索。
2. 为路线需要的区块提供不依赖可见 Mesh 的碰撞/地面数据。与主线程使用同一生成结果和碰撞算法；抽出数据层，不能手写另一套“远处没有建筑”的近似城市。视距仍只控制显示资源。
3. 导航专用缓存初始上限 128 个区块；当前路径占用按引用计数保留，结束/取消/场景退出立即释放。最多 8 个待处理路径请求。超过预算排队，不偷偷常驻整张 3D 地图；性能统计显示缓存和等待数量。
4. 加入 requestTravel/travelStatus/cancelTravel，区分等数据、真正不通、取消、到达。过期 Worker 结果不能覆盖新意图；保存或暂停时不推进位置。实际每一步仍检查静态碰撞、高度和其他具名角色体积。
5. 超过 5 模拟秒没有进展时重规划；连续 3 次失败进入 blocked，保留原因、原目标和意图。路况/目标变化后可重试。不能瞬移、穿墙、跨河或把“等待几秒”当抵达。

验收场景：集市到府衙必须过桥；玩家留在居民区时举报人仍能向府衙移动；途中存档后继续同一目的；路被挡住时等待/绕行可解释；切换场景后没有旧 Worker 结果写入新世界。实际运行证据须单独记录。

## P0-03：安全落位、办事后返回和旧档迁移

依赖：P0-01、P0-02。集中审阅点：旧档兼容。

涉及：`living/createLivingScene.js`、`living/simulation.js`、`living/persistence.js`、`persistence/worldRepository.js`，以及 `gameplay/village.js` 的所有者搬运命令。沿用 `createLivingStateIndex` 的不可变状态缓存。

具体步骤：

1. 以导航数据确认候选脚下高度、身体净空和街巷可达性；把确认后的布局与 bindings 写入 living v2。出生初始化不再要求七人的可见 Mesh 区域同时加载。
2. 新世界按归属点出生；旧世界完整校验后保留当前位置、尸体、背包、药包位置、钱、信任、案件及待回礼。闲置活人以“搬到新归属点”意图走过去；追捕、逃跑、举报、送回或回礼完成后才返回新地点。
3. 药包仍在旧摊位时，商人把它实际搬往新摊位；在玩家/捕快手中时保持持有关系，后续归还目的地使用新摊位。扩展 village 的 `relocate_pickup/relocate_deliver`，限定活着的物主到达对应地点后执行，通过原 transferLot 在 stall 与 merchant-bag 间移动；记录搬运事实且不视为偷窃。保持旧命令与旧初始状态的语义，旧档重放不能多出默认字段。搬运中持有者死亡时药包留在其实际容器，不能消失或复制。旧摊位在搬完前显示临时位置，药包已取走时不能再拿取。
4. 去掉 idle 对旧案例 home 的优先读取，统一读绑定；阿青短线活动、林岳巡逻通过同一行动接口执行。因危险中断后恢复合适行为。
5. 图形显示用渲染加载状态，导航用几何就绪状态；隐藏的角色仍保有唯一位置和意图。P0 的远处执行仅处理已有旅行和交付，不额外生成无目击依据的随机战斗。

完成标准：新档七人分布正确；旧档不重置既有结果；不存在重复 NPC、重复药包、重复回礼；同档重复打开不会重复搬迁；保存失败沿用原恢复行为。

## P0-04：找得到人，走得出第一圈

依赖：P0-03。适合在已冻结位置接口上单独实现 UI。

涉及：`ui/LivingHud.jsx`、`stores/useLivingStore.js`、`map/drawMap.js`、`ui/map/WorldMap.jsx`；拟新增 `living/placeClues.js`。

具体步骤：

1. 提供药铺、府衙、柳娘住处、石伯住处和中心商区的固定地点标记。已探索地点显示完整标记；通过明确路牌/人物告知获取的地点可提供目的地方向，不揭开整片迷雾。
2. 标记表示通常出现的地点；离岗时显示角色已告知的去向或“暂时不在”，不读取全城实时坐标追踪未知人物。旧档迁移中的药摊显示临时位置，搬完更新。
3. 近处以 E 打开单目标交互；远处给地点和距离提示。交易必须接近陈掌柜，救助必须接近柳娘；在面板里点击按钮不能跨城执行。
4. 入口给出“商街可买药，居民区有人需要帮助，府衙可以处理纠纷”的简短方向。保留两条旧事件链，不新增强制主线。

完成标准：首次进入可找到商业街；从柳娘处得知药铺方向并完成购买/救助；旧取药举报、赔偿送回能跨区域完成。此时 P0 可独立交付，不依赖后面的全部社会系统。
