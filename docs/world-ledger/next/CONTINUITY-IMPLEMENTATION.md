# 09-A / 09-B：休养、接替与不可逆后果

基线657dca6，09-A已接源码，状态REVIEWED；09-B仍在实施。下列是实施契约与源码审阅边界，不能作为运行证明。

休养只作用于活人，按真实安全休息区间每6000模拟毫秒恢复1血，即每游戏小时10血。NPC必须实际在休息场所，日程处于已到场休息，饥饿低于60且无更高优先级打断。重伤（低于60血）主动回家，休至80血再恢复常规日程。实际药物仍消耗原物品。玩家只有在有效租住点主动歇脚时才进入自然休养；需要真实自有干粮，一份支持六游戏小时，不改变药品/干粮直接使用的原效果。钱物来源全部沿用原状态。

休养采样不补算未知长间隔。关键行动在改变生命状态前先结算已确认的短休息区间，然后停止该段，避免把已经死亡的人在事后加回血。低血、离开、饥饿、追逐、战斗、菜单保存等都明确结束当前区间；已完成的实际恢复保留。旧档已死亡者不进入恢复。

代班只由登记资格且愿意接手的已有活人承担。首版登记小何根据与陈掌柜的已有雇佣约定可协助看铺；实际看到原经营者不能接待，或当面接到请求后，才可接受代班并前往原铺面。没有可用合资格者就停业。接受只是职责，实际到场/开门才做交易。看铺继续使用商铺原钱包/库存，不能复制到代班者身上；既有工资按实际代班场所记工时，原地址与既有消息目的地不被永久改写。

## 09-A 已接代码和来源

`continuity.js` / `recoveryController.js`负责实际休养与原食物；每模拟秒采样，超过1500毫秒的未知区间不补算。关键身体行动在受伤计算前结算已确认的短区间，然后停止旧段；死亡0血不能恢复。饥饿截止时间和租约截止时间限制可计入区间；生命已满时丢弃多余的治疗额度。菜单退出先停休养，再停主动歇脚/训练，再提交时钟检查点。柳娘可通过自然休养恢复，但不会因此补造玩家救助或答谢；完全康复时不能浪费药物刷一次救助。

`staffing.js` / `staffingController.js`负责合资格小何亲眼看到经营者重伤/死亡后的自愿代班。首版使用现场观察入口；远处无人看到时保持停业，不生成一名新掌柜。接受后先去原铺面，到场才取得经营权限，营业时段和真实在场仍由原场所规则控制。原经营者恢复至80血且实际回铺后交接；代班者在场见到，或后来到店读到交接便笺，才恢复自己原来的工作去处。

买卖服务、玩家按钮和NPC买粮使用实际运营者。陈掌柜的旧钱包和库存仍是同一份；原经营者死亡时，只有已到场的授权代班角色可经营该账户。没有授权不能绕过死亡限制做买卖。代班原雇佣工时按真实铺面累计；工时段记录开始工作的地点，不因交接改写历史。原经营者活着时沿用工资规则；原经营者死亡时，代班者需在铺面，凭原合同/代班授权从可支配原账户支出到期工资，现钱不足记欠付。

小何原住址/工作绑定和旧口信目标地点没有被永久改写；日程使用他已知的临时代班地点，工资使用实际有效的岗位地点。原经营者或代班者死亡不会复制钱货、复活角色或停掉其他人的铺面。遗产、未完课程和拘押/释放的详细善后继续在09-B接入。
