# 09-A / 09-B：休养、接替与不可逆后果

09-A已由a4e4f4f推送，09-B已接源码，均为REVIEWED。下列是实施契约与源码审阅边界，不能作为运行证明。

休养只作用于活人，按真实安全休息区间每6000模拟毫秒恢复1血，即每游戏小时10血。NPC必须实际在休息场所，日程处于已到场休息，饥饿低于60且无更高优先级打断。重伤（低于60血）主动回家，休至80血再恢复常规日程。实际药物仍消耗原物品。玩家只有在有效租住点主动歇脚时才进入自然休养；需要真实自有干粮，一份支持六游戏小时，不改变药品/干粮直接使用的原效果。钱物来源全部沿用原状态。

休养采样不补算未知长间隔。关键行动在改变生命状态前先结算已确认的短休息区间，然后停止该段，避免把已经死亡的人在事后加回血。低血、离开、饥饿、追逐、战斗、菜单保存等都明确结束当前区间；已完成的实际恢复保留。旧档已死亡者不进入恢复。

代班只由登记资格且愿意接手的已有活人承担。首版登记小何根据与陈掌柜的已有雇佣约定可协助看铺；实际看到原经营者不能接待，或当面接到请求后，才可接受代班并前往原铺面。没有可用合资格者就停业。接受只是职责，实际到场/开门才做交易。看铺继续使用商铺原钱包/库存，不能复制到代班者身上；既有工资按实际代班场所记工时，原地址与既有消息目的地不被永久改写。

09-B实施前先补下表的精确命令/来源。明确死亡继续保留原死亡事实和尸体财物；继承/保管与岗位接替分别登记，学费/采购/赏钱等未完成义务必须各自处理。非致命执法只能由实际合法执法攻击触发，保留1血进入失能；捕快实际接近才拘押。案件处理引用这次拘押的具体案件，不清除新案或无关案。拘押回执须满足05-B悬赏接口，不得用“靠近坐标”代替实际捕获。

## 09-B 冻结的实施边界

只在显式 `enable_justice` 后启用新行为。旧的死亡、攻击和回放均不改写。捕快的普通自卫仍沿用原伤害；只有攻击开始声明 `nonlethal`，且命中当时仍属于有依据的合法执法，才把将致死的伤害截到1血，记录 `incapacitated`。这不是复活，也不生成尸体。身体状态独立于气血，恢复药物不能解除拘押。

| 命令/触发 | 前置与依据 | 原子结果 | 退出条件 |
| --- | --- | --- | --- |
| 合法非致命命中 | 本次挥击意图、命中几何、当时执法判责/案件 | 原血量最低1、停止挥击/招架、保存失能来源及实际位置 | 现场捕获，或30模拟秒无人捕获后清醒 |
| `take_custody` | 有具名证据的活捕快、看见并在2米内接触失能者；原击倒者可凭连续身体接触辨认 | 冻结本次案件ID及当时事实，记录捕获回执，现场拘押30模拟秒 | 认缴或等到期；捕快死亡则解除控制，案件不被结清 |
| `process_custody` | 本人被拘押；认缴有足够可用钱，等待已到期 | 仅处理捕获时事实，返还仍持有的涉案财物；认缴付原钱包，等待生成具体赔偿欠账 | 1血原位释放，不给免费治疗，不清新案 |
| `pay_custody_debt` | 本人实际与有职权的活捕快会面 | 原钱包支付未清债项并记回执 | 不能重复支付；等待不是免赔 |
| `take_estate_custody` | 初始化时具名登记的保管者、实际接近并发现死者 | `estate_transfer`转移管理权限，注明死亡来源、原账户和原持有人 | 原钱货不复制、不改所有权；无保管者则保持待处理 |

首版是现场拘押，没有传送入狱或瞬间押送。30模拟秒相当于30游戏分钟，菜单不推进。捕获不需要事先接受悬赏，但领取赏金必须符合05-B的事先知晓条款。保管资格分别登记掌柜→小何、周平→另一名原捕快；这与岗位代班是不同的记录，不能因接任岗位自动继承私人财产。商铺、工资、采购和已赚取赏钱沿用原账户，保管者只可凭真实义务和现场授权办理支付/归还。

死亡终止未完课程并释放尚未支付的学费预留；已实际赚取但未付的委托报酬继续作为原账户债务。死亡不抹去持有人身上的货，失败的活送货人依据自己得知的失败/期限返回已知交货点，亲手归还原货；无可接收的人则保留货及待办，不瞬移回库。

## 09-B 已接代码和来源

`justice.js` / `justiceController.js`将明确非致命的执法命中接到原战斗、真实接触、现场拘押和案件回执。命中时依据已不成立则结束这次执法命中，不突然转成致命攻击；普通攻击路径不变。降至1血后停止动作，身体状态同时限制输入、移动和NPC行动；不会触发原来只接受0血尸体的搜刮。无人控制30秒后可恢复意识，案件仍在；拘押后可现场认缴，或30秒到期自动记录具体赔偿债并释放。释放不给额外气血，也不补发失能期间的气力。

捕获冻结具体案件及当时事实。每项赔偿有原受益账户；失款索偿引用原moneyClaim，原物实际转入捕快容器，再沿道路送回。容量不足或原物丢失则保持原物待还，可之后当面交付，不凭空补出物品。等待处理不免赔；同一事实已列入旧结算的款项不会在另一名未获知结案的捕快那里再次收取。新证据不被旧的事实范围抹去，其他捕快仍需获知实际结案回执。悬赏沿05-B既有捕获凭证结算，事后读告示不能追认之前的捕获。

`estates.js`先做明确的保管授权，不做现金分家：小何/另一名原捕快必须亲眼发现并靠近登记死者，才获得原账户的限定办理权限；死亡、原钱包、原容器、所有权和岗位记录分别保留。工资继续走09-A的原工时/经营账户。已交差但欠付的跑腿费、已完成护送报酬、已完成捕获的赏金保留源回执和预留；保管者在登记地点、实际会面时可从原账户付清，没有钱就继续欠着。没有具名保管人、保管人也死亡或尚未到场，保持待办。

失败送货人的归还路线独立于已结束的任务状态，依据本人获知的失败/期限和原固定交货点；不追踪远处人物实时位置。玩家也可在现场交回原货。未完教学在实际死亡或显式启用新版时对照原死亡事件终止，未付学费预留释放，不发能力加成。界面区分死亡、失能、拘押、欠赔与原账户领款，回顾能追到来源。

源码审阅与Git差异检查覆盖上述入口、原子失败、重复结算、来源范围、真实持有/返回和旧版本门控。尚未运行真实挥击、读档恢复、拘押计时、UI操作、容量、性能等场景。现有保管是权限移交，不是已完成完整继承分配或建好监狱押送；这两项不属于本版范围。

## 09-A 已接代码和来源

`continuity.js` / `recoveryController.js`负责实际休养与原食物；每模拟秒采样，超过1500毫秒的未知区间不补算。关键身体行动在受伤计算前结算已确认的短区间，然后停止旧段；死亡0血不能恢复。饥饿截止时间和租约截止时间限制可计入区间；生命已满时丢弃多余的治疗额度。菜单退出先停休养，再停主动歇脚/训练，再提交时钟检查点。柳娘可通过自然休养恢复，但不会因此补造玩家救助或答谢；完全康复时不能浪费药物刷一次救助。

`staffing.js` / `staffingController.js`负责合资格小何亲眼看到经营者重伤/死亡后的自愿代班。首版使用现场观察入口；远处无人看到时保持停业，不生成一名新掌柜。接受后先去原铺面，到场才取得经营权限，营业时段和真实在场仍由原场所规则控制。原经营者恢复至80血且实际回铺后交接；代班者在场见到，或后来到店读到交接便笺，才恢复自己原来的工作去处。

买卖服务、玩家按钮和NPC买粮使用实际运营者。陈掌柜的旧钱包和库存仍是同一份；原经营者死亡时，只有已到场的授权代班角色可经营该账户。没有授权不能绕过死亡限制做买卖。代班原雇佣工时按真实铺面累计；工时段记录开始工作的地点，不因交接改写历史。原经营者活着时沿用工资规则；原经营者死亡时，代班者需在铺面，凭原合同/代班授权从可支配原账户支出到期工资，现钱不足记欠付。

小何原住址/工作绑定和旧口信目标地点没有被永久改写；日程使用他已知的临时代班地点，工资使用实际有效的岗位地点。原经营者或代班者死亡不会复制钱货、复活角色或停掉其他人的铺面。遗产、未完课程和拘押/释放的详细善后继续在09-B接入。
