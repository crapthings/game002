```text

本次只实施 P0-01：从现有城市规划解析地点，并为当前七名具名 NPC 建立归属绑定。不要在这次启用角色搬迁、修改存档格式或实现其他卡片。

先核对当前工作区和最新 origin/core；计划基线是 3027b81。保留已有本地修改，按实际新版本核对接口。继续使用现有引擎、模型、地图、碰撞与性能优化。

按 P0-01 明确的输入、输出、候选排序和完成标准实现，新增文件使用项目已有 JavaScript ESM 风格。不要修改旧 worldLedger/firstLoop.js 的 NPC 定义来搬动新场景。候选地点只标为待运行时确认，不能把未经碰撞确认的坐标宣称为安全落点。

当前仓库不运行测试、build、lint。完成后做允许的源码与差异审阅，说明哪些场景尚未实际运行；不要改写规则文件来解除限制，也不重复要求我确认这些已明确的限制。

交付当前卡的代码、选址依据、实际文件清单、兼容性影响及尚未验证事项，并在本文件状态表记录结果。按我们现有分支协作约定交付。完成当前卡后不要自动展开全部 12 项。
```

此提示词只启动 P0-01。继续下一张时，把“本次只实施”的卡号、目标和需读的任务文件一起替换，附上前一张的提交与尚未解决事项，不再粘贴全部历史聊天。

## 执行节奏

日常配置、文本和 UI 可以在已明确接口上逐卡执行。下列改动应先形成具体结构/差异，再由 B 或一次集中审阅确认契约是否完整：P0-02 导航数据生命周期、P0-03 旧档位置迁移、12-A 版本演进、04/06/07 的资金与交付事务、05-B 权威职责替换、09-B 失能/死亡、12-B 归档、12-C 远近时序。

这是任务的审阅顺序，不是要求每次更换模型，也不要求每一步都向用户申请权限。低思考强度不改变完成标准；发现不满足条件时记录具体问题和最小修改范围，避免用更多硬编码掩盖问题。

每卡结束提交以下信息：

```text
卡号：
实现状态：TODO / IMPLEMENTED / REVIEWED / RUNTIME_VERIFIED
基线与实际提交：
修改文件：
玩家可观察变化：
接口及旧存档影响：
实际验证方式和结果：
尚未运行/尚未解决：
下一张卡及依赖是否满足：
```

提交时间不能决定冲突里保留哪一边。A 的性能优化与 B 的规则改进需同时保留，特别核对 Worker 生命周期、不可变状态索引、钱物唯一状态、个人知识和保存确认。当前功能分支吸收 core 的新改进，再按约定进入 core；dev/main 不由计划自动发布。
