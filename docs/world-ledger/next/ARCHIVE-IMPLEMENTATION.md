# 12-B：分页、引用与保存事务

状态：已实现并进行源码审阅；没有运行测试、build、lint、浏览器或容量试验。不能据此声称长期容量或性能已经验收。开发基线 47c3a27，Goal 继续后续卡。

## 保存结构

- gameplay 仍为 v2，首次归档后 `archive.version=2`，新增 `archive.history={version:1,id,pages,requestIndex}`；首次归档才升级 living v4 / document schema 6。
- 原始 `archive.legacyCheckpoint` 完整保留。v1 冻结读取器不变；旧 living v1/v2/v3 仍可读。
- 每页包含从上一边界以来的原始 journal、各域新事件、原回执、起止 revision 和目录范围。当前 journal 清空只发生在候选副本；保存确认后才发布。
- 512 个活跃请求或任一事件域达到 1024 条时准备一页。各 reducer 的 4096 活跃窗口保护仍存在，抢劫一次可能两个事件，仍预留两个位置。
- 每域保留全局事件序号、保留记录数和旧回执索引；递增序号不依赖已裁剪数组的长度。请求 ID 指向原页和位置，内容相同返回原成功，内容不同拒绝。

## 可以移走什么

v1 策略只裁剪没有当前投影引用的日常活动、到达、打断、服务在场、出招/招架、行踪、换面巾、已累计工时和已付工资等记录；保留每域首条、每人物每种活动最新记录及明确引用。相应无人获知的普通事实可移到历史页。

案件、伤亡、财物所有权、个人目击/转述/关系、委托结算等规则仍需查询的记录保留在活跃投影。匿名记忆与具名记忆同样保留，归档不赋予任何人物知识。因果祖先可以在旧页，通过目录读取；工资累计时长、已付次序、欠付和委托终态不重置。

案件判定所用的攻击起点及同一侵害的父事件链也留在规则索引中，避免较晚报案时因找不到出招事件而改变 incidentId。旧 `village:legacy:…` 非数字 ID 另有目录映射，不用数值范围猜来源。

原回执信息同时留在历史页及域内回执索引，不能通过换请求号重复已经兑现的语义操作。`live-N` 起点也检查归档请求 ID，包含此前失败尝试留下的编号间隙。

## 恢复与提交验证

读档从冻结 v1 原档恢复，建立 v2 基线，按页顺序重放 journal，在每一边界重新推导归档内容，再比对实际页和目录，最后重放当前 journal 并比较完整投影。页缺失、顺序/内容不一致、投影损坏都拒绝；没有接受任意快照的快捷入口。

IndexedDB repository 仅在完整恢复后保留私有基线副本。后续保存重放相对该基线的增量，重新推导待写页并比较整个候选玩法；成功事务后才替换私有基线。时钟保存同样核对 sequence 与递增时间。世界几何不恢复成每次保存重新生成/解析的旧实现。

数据库升级为版本 2，增加 history store。新增页使用 add，进度使用 revision 比较；二者在同一个 readwrite 事务完成。写满、重复页、冲突或失败会回滚整笔事务；不删除旧页，不半清空旧日志。未知保存结果仍要求重新读取，不能继续在不确定的分支上发奖。

同步 localStorage 路径以一个 JSON 文档携带全部页并一次 setItem；保留其原配额限制。导入 IndexedDB 时世界、进度及原有页也在同一个事务内完成，原 localStorage 字节保留。

## 回顾与边界

关闭回顾不加载 UI 历史。打开后先用保留记录；“翻阅一页旧账”和跨页来源按钮才请求页面，读取失败展示原因。卸载面板/换世界后丢弃过期异步结果。

为验证完整来源，启动恢复仍会读取所有归档页，当前把已读页保存在规则层缓存；它们不随每次玩法 structuredClone 复制，但总内存与启动重放成本仍随历史增长。个人证据、契约投影、预留回执和所有权链仍可增长；本卡没有承诺无限历史或恒定内存。委托实体、资金/物品预留的独立 4096 容量保护继续保留，不能用归档掩盖尚需索引的状态。

后续运行验收应覆盖：跨过旧活跃窗口、归档奖励请求重试、不同内容同 ID、存档后重新进入继续编号、跨页 cause、匿名记忆、欠薪/运输、页缺失、事务配额失败与并发标签页冲突。当前仅源码追踪这些路径；实际容量问题是否解决和性能结果仍待授权下的运行证据。
