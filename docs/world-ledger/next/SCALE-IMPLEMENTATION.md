# 12-C：远近决策、前台休息与规模观察

实施基线为cfee485，实现提交fc7d55b。当前根AGENTS.md禁止运行测试/build/lint。本卡完成实现和源码审阅；没有运行浏览器、采集FPS或验证存档恢复，下面的观察步骤不是已完成的验证。

## 同一时钟与身体

`living/lifeCadence.js`接原simulation：32米以内普通轮询为1模拟秒，之外为5模拟秒，按稳定角色ID错峰。日程边界及饥饿60、疲劳25、紧急休息恢复65的阈值可提前唤醒；伤害、吃饭、恢复和活动中断等实际事件可唤醒本人。轮询不增加第二套需求、位置、钱包或随机事件。

场景在移动玩家前取得本步可推进的时长。下一到期点限制全世界时钟；同一时刻尚待处理的人物在该时刻依次处理，处理完才继续。没有把较早的命令倒填到已经发生的交易之前，也不在五秒之后逐帧重放整座城。未结承诺、危险和自己的当前活动仍优先；刚到上班时间且没有在办约定的人先切换日程，再考虑接新活。

低频部分是普通日程、吃饭/缺货轮询、普通传话和新日常活动的发起。已有行走、身体碰撞、战斗扫掠、举报/追捕、当面交付、未完帮运、训练和休养采样保持细粒度检查。原导航Worker、128区块数据预算、2个几何任务并发、真实路线与失去视线后的固定记忆继续使用。没有用“离开视野”替代履行、目击、消耗或恢复。

`createStreamedWorld.bodyLocationStatus`在相邻几何完整、原坐标地面高度和通行规则符合时才返回ready。模型首次启用/重新进入加载区还要避开玩家和已启用人物；缺几何、地形受阻、等待让位分别计数。原NPC ID、物品、位置和待办保持不变，不重新出生或把受阻人物传送到随机点。若原坐标本身非法，当前保留并标记受阻；不宣称已提供任意损坏位置的自动修复。未启用的近处身体不能成为可见目击、攻击或交互目标；远处实际会面仍依赖已确认的导航地面数据。

## 独立休息入口

玩家在有效租期、指定地点、已经安全歇脚时，可以选择“加快休息一小时”。每个前台画面最多增加4个原物理小步，每小步不超过50毫秒，并有6毫秒追加工作预算；实际速度最高约5倍，保存等待和机器负载可使其更慢。每一步都经过相同世界时钟、边界、实际移动和规则校验，后台环境人群及玩家非移动气力按实际增加的世界时长推进。

遇到待确认提交时停止本帧追加；危险、追捕、租期结束、当面回礼/交代事情或玩家其他操作结束加速。可以主动停止。菜单/失焦清理/读档不自动重启加速，离线墙钟不参与补算。既有恢复仍需真实食物与合格休养区间；没有直接加满气血、跳过路程或按睡眠时长一次性发奖励。

## 保存及兼容

新增可选living字段`cadence`和`population`，玩法和文档版本不变。旧档缺字段时从原世界时间继续，按现有正常9人到达策略读取，不依据URL改写已有种子。cadence校验角色ID、时间、间隔和至多一个周期的下次到期值；复用原检查点保存顺序。字段只记录调度，不绕过玩法重放验证。新到达仍在一个原子检查点内登记各域、住处、身体和有限原有钱粮；既有角色资源模板未改。

## 观察入口与记录

开发模式的新种子可用`?livingPopulation=7`或`?livingPopulation=12`固定观察人数；无参数为正常9人策略。7人为最初七名具名NPC，不自动到达货郎和渡口联系人。12人为七人、原两名到达者和三名普通街坊；三人需先有实际几何确认的独立住处，再依次登记，参与同一健康、生活、钱物、知识和犯罪规则。背景人群不计入这7/12人，玩家另计。

同种子在同一浏览器存储中不能切换人数。对比应在两份独立的浏览器资料/隔离存储中创建相同种子，或使用已备份的各自原始观察档；不删除正式存档。若某处几何不成立，面板保留当前已到达人数，不将未到达算成12人。

图形设置启用性能面板后，每约0.5秒采样，新增：具名人数及目标、近/远轮询次数、边界停留帧、身体待几何/地形受阻/等待让位、保存次数/失败/最近/平均/最慢/当前等待、活跃请求和归档页/条数。轮询计数表示处理机会，受危险抢占或失能时也可消耗该机会，不等于写入新事实的次数。未发生保存为“暂无数据”，不支持GPU计时仍显示不支持。

“采集60秒”保留最多140份真实样本并可下载JSON。记录画质、画面尺寸、种子、人数、玩家位置、世界时间、每窗帧数/时长、已有CPU/GPU/导航/区块统计及新保存/历史指标。暂停、人口/画质/种子变化会标注中断或条件变化。记录不写入玩法档；`codeCommit`留空，观察者须把当次实际Git提交填入附注，不能用玩法revision冒充代码版本。`scenario`只是约定路线名，采集器不会自动证明玩家走了完整路线，应核对位置轨迹。

建议将当前提交和cfee485的正常9人版本分别观察，以比较本次调度改动；再在当前提交比较7人与12人。7人缺少后两名经营/帮派人物，因此7对12反映扩展后综合负载，不应解释为单个NPC的纯边际开销。

固定条件：同一种子、同一硬件/浏览器、同一画面大小、视距64米、渲染100%、正常世界速度、同一起始存档和世界时间。待目标人数到齐、区块及素材加载结束后，在便笺处预热30秒。沿“便笺→药铺→街心茶摊→府衙→住宅区”相同道路分段记录，每段60秒；未走完就继续下一段。按相同位置区间比较，记录暂停、转向、交战和保存等待，不能把不同路段均值直接相比。日程、人群和实际交易仍会影响场景负载，应保留原始样本。

FPS按总帧数/总窗口时长汇总，CPU按窗口帧数加权；同时报告最慢窗口、导航队列峰值、区块峰值、保存增量等待、历史增长和是否发生身体受阻。采样记录只能支持对应场景，不能据此保证长期容量、十二人所有组合或更大规模。
