# World Ledger 事后因果回顾

当前代码基线：core / d2a43d7。本页记录已编写功能和待执行验收，不代表运行通过。

## 使用方式

打开“事后因果回顾”，默认显示全部已记录事实。可用回顾范围选择某次拿取、救助或交易，只显示由其引起的事件。点击事件标题选中它；“源于”指向直接原因，“直接后续”指向已发生的后续。尚未发生的报复、举报或回礼不会作为预测插入账本。

拿取链呈现拿取→目击→举报，以及拿取→交还赔偿→送回；救助链呈现救助→当面回礼。交还不要求已被举报，因此交还的直接原因是拿取，不能伪装为必经举报的线性剧情。

展开“角色各自知道什么”，显示六名参与者在所选范围内的目击、举报或救助记忆。每条记录可查看依据。匿名目击与匿名救助不会显示为识别了玩家；案件了结仍保留历史记忆。没有相应记忆时明确显示没有记录，不代表角色没有其他生活经验或交易行为。

## 实现边界

- LedgerReview.jsx 为只读展示组件，只更新本地选中状态。
- 场景发布经过字段选择的事件、案件、知识和救助副本；回顾不持有规则对象或事件details引用。
- 按已验证账本的先因后果顺序归组，不产生新事件，不改存档、好感或身份识别。
- 这是明确标注的事后全局事实视图，角色行为继续读取自己的知识。

## 待统一验收

1. 无事件时显示空状态；选择范围后仍能返回全部。
2. 具名拿取后，在同一链查看目击、举报、交还及实际送回；源于和直接后续均能选中正确事件。
3. 蒙面拿取后，已目击角色的依据显示身份不明；未获消息的角色不显示知道拿取者身份。
4. 捕快收到举报前后，知识来源与账本一致；结案后历史记录仍可追溯。
5. 具名救助和回礼归为同一链；匿名救助不显示认出玩家或凭空回礼。
6. 多次案件与交易穿插时，选择旧案件不会混入新案件；回顾开关与选择不改变铜钱、物品、知识或事件数量。
7. 暂停/返回游戏、切换世界、存档恢复后，界面无失效选项或错误事件关联。
8. 用Tab聚焦背包/交易/回顾按钮后，空格执行按钮操作而不触发角色跳跃；方向键操作选择框时不触发移动或冲刺。离开控件后正常移动，松开按键不出现卡住移动。

交互修正：HUD内按钮、选择框和折叠摘要的空格/方向键保留浏览器原生行为，阻止传入世界移动监听；keyup仍传递以释放已有移动状态。命令批次仅在规则revision实际改变时请求即时检查点，失败操作仍显示原因，正常定时保存与NPC新事件保存继续工作。

## 知识更新修正

捕快先在识别距离之外目击拿取，随后收到他人的具名当面举报时，知识从身份不明升级为玩家，并指向该举报证据。匿名信息不会覆盖已有具名知识。这个情况针对未蒙面、不同观察距离；全程蒙面仍不会凭空识别。

读档从目击和送达报告推导应有的知识集合，遗漏或多造知识记录均拒绝。兼容早期“保留第一条知识”的完整旧投影，载入规则时只依已有证据升级；不重新送达举报或结算赔偿，不从全局玩家身份补齐匿名信息。
