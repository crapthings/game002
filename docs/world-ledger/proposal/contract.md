# World Ledger 数据模型与接口规范 v0.1.0-draft

状态：**A/B 待审阅的接口草案，尚未冻结、尚未接入真实场景**。维护者：用户 B 的 Codex；共同审批者：用户 A、用户 B。配套文件：`world-ledger.d.ts` 是便于检查的 JSON DTO 参考，`example-scenario.json` 是设计样例。它们不代表已选定最终语言、引擎或序列化库。

## 1. 目标、范围与责任

目标是证明：玩家行为被有限的目击者知道，经合理途径传播，触发有动机、有延迟、可追溯的后果。第一轮使用已有 Babylon 场景进行技术验证；Unity 武侠 GTA 是未来产品候选，当前没有迁移决定。

两条最小闭环：

1. 偷窃完成 → 事件时刻的有效目击 → 个人认知 → 实际送达的举报 → 官府证据评估 → 调查/追捕或有资金的悬赏 → 执行回执。
2. 救助完成 → 获救者感知/认知 → 有向感激关系 → 延迟帮助计划 → 前置条件复核 → 实际帮助完成或明确失败。

用户 A 拥有世界生成、实体生成与位置、移动、碰撞、遮挡与感知采样、NPC Goal 的导航及动作执行。用户 B 拥有账本、关系、认知传播规则、犯罪/悬赏评估、NPC 动机与计划、延迟队列及因果查询。B 不能把“计划追捕”写成“已经抓到”；A 不能因动画播放就宣称事件完成。双方只通过已审阅的适配器接口交换消息，B 暂不修改 A 的世界生成模块。

MVP 不含完整开放世界、自由自然语言推理、战斗数值平衡、跨城经济、传统长支线、多人生存或全 NPC 长期模拟。第一轮的规则可完全确定、无需 LLM。

## 2. 通用字段与事件时间

| 字段 | 约束 |
|---|---|
| `schemaVersion` | 当前固定 `0.1.0-draft`；未知版本拒绝，不静默猜测 |
| `worldId` | 持久世界标识；不同世界的事实、存档、回执不得混用 |
| NPC / Entity / Event ID | 稳定、不含姓名职业或隐藏身份语义的 opaque 字符串；不能按数组下标、当前显示名或位置重建 |
| `occurredAt` | 原事实发生的模拟时间，整数毫秒；墙钟不参与因果规则 |
| `recordedAt` | B 接受并记录事实的模拟时间；可以晚于发生时间 |
| `sequence` | B 按世界分配的连续追加序号；A 不指定，全局顺序以此为准 |
| `causeEventIds` | 指向已存在、序号更小的直接原因；不允许自引用或循环 |
| `correlationId` | 一条交互链的追踪 ID；不是权限凭据 |
| `idempotencyKey` | 在 `(worldId, producerId)` 内唯一；同 key 同内容返回原结果，不重复产生后果 |
| 位置 | 米，带 `spaceId`、`zoneId`、`frameId`、`capturedAt`；坐标轴映射由 A 在适配器实现并双方确认 |
| 金额/概率 | 金额使用最小货币单位的非负安全整数；概率在 `[0,1]`；拒绝 NaN / Infinity |

`tick.now` 只能前进或保持，暂停游戏不推进队列。允许延迟送达的事实保留旧 `occurredAt`，但不能倒写已经追加的账本。新的举报发生于送达时，`claim.happenedAt` 仍保留原事件时间。事件时刻的感知帧必须由 A 保存；不能在一分钟后读取当前位置来补造当时的目击。超出约定采样窗口、帧不匹配或缺少证据时返回错误并保留诊断，不能默认“看见”。采样容差的具体毫秒数待 A/B 根据引擎 tick 共同冻结。

## 3. 对象字典与私密边界

### Event：事实账本

`EventRecord` 是不可变事实，包含通用信封与判别式 `fact.type + fact.payload`。A 只提交 `EngineFact`；B 的规则只能产生 `LedgerFact`。例如 `action.theft_completed` 必须已有库存/所有权转移凭据 `transferId`，失败的偷窃尝试不能伪装成完成。`action.aid_completed` 也必须有真实救助结果。

账本保存真实 actor ID 供可信系统审计。这个 actor ID **不等于**每个 NPC 已经认出行为人。不得把原始事件直接给 NPC 对话、玩家 UI、面向玩家的日志或 LLM。不存在“大家自动知道所有事件”的订阅通道。

### Relationship：有向关系图

每条关系是 `fromId → toId`，含关系种类、强度、知情者、来源事件与过期时间。亲属关系如果需要双向，显式创建两条边。亲属/朋友关系不自动授权查看对方所有认知；必须有一次真实信息传递。感激关系必须来自获救者自己的有效认知，不能仅因为账本有救助事实就直接写入。

### Knowledge：每个 NPC 的认知

`holderId` 指认知持有人；`claim` 是其相信的内容，不保证等于真实事实。来源区分直接观察和他人举报，保存信源、父认知、送达事件、置信度、传播跳数与状态。`auditSourceEventIds` 仅供 B 的审计，不允许 NPC 以该字段查询真相。冲突认知并存并标记 disputed，不覆盖旧记录；纠错追加状态变更事实，不改历史。

`claim.lastKnownPosition` 是认知中实际携带的最后已知位置，可以为 null。调查/追踪 Goal 的 `locationKnowledgeId` 必须属于执行 NPC 可访问的有效认知，且 Goal 坐标与该认知位置一致；不能读取目标当前真实坐标填入此字段。转述可以损失精度、只剩 zone，但不能无证据提升定位精度。

跨 NPC 转述必须创建收件人自己的 `Knowledge`，`parentKnowledgeId` 指原条目。收件人不能直接拿发送者的条目充当自身认知。MVP 传播上限与置信度衰减是版本化规则；避免往返传话无限增信。建议草案上限 3 跳、转述置信度不增加，具体数值由 A/B 冻结。

### Witness：感知证据

由 A 提供 observer 与目标在同一事件帧的坐标、距离、感知范围、视场检测、射线遮挡结论、模态与识别证据。B 验证字段一致性并据此生成认知，不能反向要求 A 证明预设的嫌疑人。

视觉目击至少满足：`perceptible=true`、`fieldOfViewPassed=true`、`lineOfSight=clear`、距离不超过感知范围、帧和时间一致。听觉使用 `fieldOfViewPassed=null`、`lineOfSight=not_applicable`；听见声音本身不能证明“看到某人的脸”。`perceptible=false` 的样本可以供审计，但不能产生肯定认知。

### 身份与隐藏身份

`ActorProfile.privateTraits.hiddenRole` 只在可信模拟与该 NPC 的自我能力决策中使用。`PerceivedSubject.handle` 是观察者/认知作用域内的外观对象，`recognizedEntityId` 默认 null。只有有效识别证据才能填入真实稳定实体 ID。`appearanceToken` 表示当时外观，不能隐含隐藏职业；不同伪装不可自动合并。

转述不会自动完成身份解析。守卫可以追查“穿红衣的陌生人”，但不能因内部账本知道 actor ID 就瞬移追踪本人。即使认识名字，也不代表知道此刻位置。NPC Goal 用最后已知位置和感知对象执行；追丢必须报告 `target_lost`。公开身份与隐藏身份分别投影，玩家因果查询只返回其已发现的节点；完整因果链仅用于明确标识的开发审计视图。

已认识的公开身份通过 `identity.familiarity_registered` 表达：只允许场景初始化的已知关系，或实际完成的可信介绍；自报假名不构成可信介绍。样例使用场景种子中的旧相识作为识别前提，并让 Witness 引用该前置事件。没有此类识别依据时不可偷偷把真相 ID 写入观察者认知。`Relationship.toId` 为权威关系端点；对于尚未识别的陌生帮助者，MVP 保留对外观的感谢认知，识别建立后再创建可跨外观关联的持久感激边。

### Faction / Crime：机构与证据

势力不是全知信息总线。只有实际送达该势力收件人并进入 `inboxKnowledgeIds` 的证据，才能支持机构决定。成员私人知道某事不意味着整个势力知道。`Crime` 的嫌疑人、置信度、状态由机构可访问认知评估，不能直接读取真实 actor 字段。证据不足可调查，认错/失效可撤回；严重度不是全世界统一通缉星级。

### Bounty：有资源约束的委托

发布者、动机认知、目标描述、金额、资金保留凭据、有效期与承接人必须明确。状态：open → claimed → completed；open/claimed 可取消或过期。资金先保留再发布；重复发布/承接/完成不重复冻结或付款。每单同时至多一个承接人，用原子状态条件防止抢单。过期退款、完成付款必须与幂等状态转换同一事务或可恢复事务记录绑定。

MVP 只用 `locate_and_report` / `apprehend`，不需要“随机刺杀”来验证概念。隐藏职业 NPC 可以因自我能力选择承接，但其他 NPC/玩家不会因这次筛选自动获知其隐藏职业。杀人/击杀悬赏是后续设计，当前接口不承诺。

### NPC Reaction：计划与执行

反应由 NPC 已有认知、关系、性格/能力、资源、风险、距离可行性等决定。`Reaction` 记录触发认知、原因事实、规则版本、生效时间、到期时间和执行状态。同一触发链必须有去重标识或规则去重索引，不因每帧 tick 重复生成计划。

外部动作通过 `EngineGoal` 发给 A；B 内部的发布悬赏/拒绝交易等状态变化由规则事务完成，**不是每个 Reaction 都必须有 EngineGoal**。`accepted` 只证明 A 接收，`running` 只证明进行中；只有终态回执与对应完成事实能将计划判为成功。

## 4. 输入、输出与执行回执

| 方向 / 方法 | 含义 | 不代表什么 |
|---|---|---|
| A → B `ingest(FactInput)` | 提交已发生动作、感知帧、送达、执行回执 | 不要求 B 接受无效目击 |
| A → B `tick(TickRequest)` | 推进模拟时钟并提供相关角色存活/可用状态 | 不允许凭空补齐缺失状态 |
| B → A `EngineGoal` | 交给指定 NPC 的行动意图与过期时间 | 不代表物理动作已经完成 |
| A → B `GoalReceipt` | accepted/running/终态，附引擎版本和结果事件引用 | 没有结果的 accepted 不能触发成功奖励 |
| B → A `queryGoal/cancelGoal` | 重连/读档对账与明确取消 | 查无结果不能直接重做不可确认动作 |
| B → 消费端投影 | NPC 本人认知 / 玩家已发现因果 | 不是原始账本或完整身份图 |

典型流程：B 产生举报反应 → tick 输出一次 `deliver_report` → A 导航至收件人 → A 生成 `report.delivered` 与 succeeded 回执 → B 接收送达事实、创建收件人认知 → 机构评估。为了避免“结果事件先有还是回执先有”的循环，A 预分配 `receiptId`，先提交完成事实取得 event ID，再提交引用该 ID 的终态回执；B 将完成事实视为发生依据，回执结束 Goal。允许同一受控提交批次实现，但不要求第一版必须有批量 API。

`report.delivered` 中的知识必须属于发件人且仍可转述，收件人、Goal、回执 ID 和空间位置一致。A 不能生成自己的 `knowledge.acquired`。帮助 Goal 成功应有新的 `action.aid_completed` 事实；追捕成功若仅实现“到达最后见到的地点”，不得声称“逮捕成功”。MVP 可以只完成调查/追踪验证；完整拘捕结果在扩展事件类型并双方审阅后接入。

`expectedWorldRevision` 是前置条件提示而非一帧变动就必然拒绝。A 要检查与动作相关的事实（存活、目标可识别、路径/物资等）；无关世界版本变化不应造成无限失败。

## 5. 延迟与状态机

队列按 `(dueAt, -priority, id)` 稳定排序，时间全部来自模拟时钟。每次 dispatch 前重新检查 NPC 存活/可用、认知是否仍 active、悬赏是否有效，以及是否到期。必要状态缺失则 fail closed，返回前置条件错误或保留待检查，不能默认活着/可达。

Reaction：planned → queued → dispatched → succeeded/failed/cancelled/expired。内部即时反应可从 planned 直接进入 succeeded；必须有支持状态转换的账本事实。ScheduledItem：pending → dispatched → completed，或 cancelled/expired。不存在因睡眠现实 10 分钟而自动推进暂停中的游戏。

重试只适合暂时不可达等明确可恢复失败；应设最大次数与下一次模拟时间。失败后新尝试拥有新 Goal ID 并关联原 Reaction；网络重传仍使用原 Goal ID 和幂等 key。NPC 死亡、认知撤回、委托取消或过期时，取消待发计划；已派发的 Goal 必须请求 A 取消并等待回执，不能假设物理动作已停止。

## 6. 因果、幂等与一致性

1. B 为每次成功摄入保存 canonical payload hash 与处理结果。相同 key + 相同内容返回原 event ID 和 `duplicate=true`，不得再执行规则；相同 key + 不同内容为 `DUPLICATE_CONFLICT`。
2. 事实追加、其派生认知/关系、规则去重索引及队列写入必须原子提交，或使用具备可恢复提交状态的事务。不能只写了事件却因重传去重而永久漏掉派生结果。
3. 因果图引用必须存在且向前追溯，禁止使用将来事件证明当前行动。跨界异步结果只在送达后触发规则。
4. 传输可重试；执行效果不能重复。A 保存 Goal 执行日志，以 `(worldId, goalId)` 幂等接收、保存终态结果。
5. 示范回放使用固定排序、固定规则版本、固定 RNG 算法与状态。不要使用系统随机数或当前墙钟参与规则。
6. 已记录事实不能编辑或删除以“修正结果”。认错、撤回、悬赏取消均用新事实表达。

首版重新模拟的复现条件是**相同的已排序输入序列 + 相同 seed/RNG 状态 + 相同 rule/schema 版本**。B 的摄入 sequence 按实际接受顺序分配，不保证同一 tick 的输入在不同网络乱序下仍产生相同计划。A 若需要统一同 tick 顺序，应在提交前按双方冻结的键排序，或另行扩展批次/水位线协议；当前不假装已经具备该能力。

投影方法的调用者权限由宿主适配器的可信上下文提供；不能只凭调用参数里的 `holderId` 就授权任意 NPC 查询。NPC 投影剔除原始审计链与身份识别证据事件 ID，保留其本来认识的公开实体身份；玩家投影使用独立 view ID，避免通过内部引用推断隐藏对象。

## 7. 存档与重放

`LedgerSnapshot` 保存对象状态、完整既有事件与感知证据、末序号、时钟、随机状态、去重索引、未结束 Goal 与已知回执。MVP 把完整历史纳入快照以避免因果引用丢失；后续外置不可变事件存储时再扩展归档定位和校验协议。快照与日志尾部的 world/schema/rule 版本和校验值必须匹配。规则升级需要显式迁移函数和迁移记录；没有迁移器时拒绝加载。

加载时先恢复快照，再按 sequence 应用尾部事实，**重放不重新执行规则、不产生新的 ID、不重新向引擎下发副作用**；因为派生事实已经在日志里。对照测试可以另行从同样输入重新运行规则以比较输出，但这属于重新模拟，不是存档重放。

恢复后对每个 outstanding Goal 调用 A 的 `queryGoal`。A 返回已有终态时补录相同回执；running 时继续观察；未知时标记待对账并保留原 key，只有确认没有执行后才可重派。断线/崩溃的未知结果不得直接当失败重做。`restore` 在对账结束前的 `engineGoals` 应为空。

MVP 校验算法草案：UTF-8 JSON，对象键按 Unicode code point 升序，数组保留业务规定顺序，省略对象的 absent 字段但保留显式 null，整数无前导零，字符串采用 JSON 转义，禁止非有限数字；对快照除 `checkpointHash` 外的内容计算 SHA-256。具体规范化实现应由 A/B 选定并用双方共用测试向量冻结，避免不同语言 number/string 转义实现分歧。当前草案不声称 Babylon 与 Unity 物理重演必然一致；只承诺在相同已记录事实下验证 B 的投影重放。

## 8. 错误契约

统一 `Result<T>`，失败返回 code、简短 message、是否可重试、correlationId 与 fieldPath。错误不能悄悄返回空数组伪装成功。

| 代码 | 例子 | 处理 |
|---|---|---|
| SCHEMA_UNSUPPORTED / WORLD_MISMATCH | 不认识版本、跨世界回执 | 拒绝；不重试原包 |
| INVALID_VALUE / UNKNOWN_REFERENCE | 非法置信度、不存在的 NPC/事件 | 修正输入后使用新的 key |
| DUPLICATE_CONFLICT | 同 key 内容不同 | 停止该输入流并调查 |
| TIME_REGRESSION | tick 比当前时间早 | 拒绝倒退；旧事实不等于旧 tick |
| STALE_PERCEPTION / INVALID_EVIDENCE | 用现位置补当时目击、墙后可视认知 | 不产生肯定认知 |
| ILLEGAL_TRANSITION | 已完成委托重新承接 | 返回既有状态或明确拒绝 |
| PRECONDITION_FAILED | NPC 已死、资源已耗尽 | 取消/失败或按规则有限重试 |
| UNAUTHORIZED_PROJECTION | NPC 请求真相/隐藏身份 | 拒绝 |
| SNAPSHOT_MISMATCH | 日志缺口、哈希或版本不符 | 停止恢复并保留原文件 |

## 9. 两条样例链与当前证据边界

`example-scenario.json` 包含一个同城小样例：实体使用无职业语义的 ID；目击者看到玩家偷商人物品，完成面对面举报；守卫据送达证据生成 wanted Crime，并为寻人发布已保留资金的悬赏。玩家另行救助居民，居民生成感激关系及到 70,000 模拟毫秒才生效的帮助计划。该计划当前仍在 pending；样例**不冒充已经运行或完成帮助**。

样例是“场景状态 + 原因事实子集”，`events` 不是可独立恢复完整最终状态的全量日志。最终状态对象在顶层数组提供，目的在于检查字段、引用和接口。完整 replay fixture 必须记录每一个派生 `LedgerFact` 后再交付，不能把本例当重放通过证明。

## 10. 必须验收的行为

| 编号 | 输入/条件 | 可观察期望 |
|---|---|---|
| W01 | 视距内、视野内、无遮挡偷窃 | 有效 Witness → 仅目击者先获得 Knowledge |
