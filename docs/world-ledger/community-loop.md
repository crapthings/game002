# 第二段实现：合法道具与善意回报

当前基线为 core / d2a43d7（生成器与存储 v10），接续第一阶段本地代码。用户要求持续实现、统一验收；不运行根规则禁止的测试、build 或 lint。旧 v9 世界不会自动迁移到 v10。

## 玩家现在可做的选择

- 靠近陈掌柜，购买止血药（15文）或干粮（5文）；库存分别4/6份。交易同时扣钱、扣商店库存、增加玩家自有物品，并记事实。
- 背包容量6件，初始一份干粮。陈掌柜的涉案药包单独保留所有权，不与自有药品混合，也不能拿去消耗或救人。
- 可向陈掌柜出售自有止血药（7文）或干粮（2文），每次一份；减少背包数量、补回商店库存并转账。商人初始60文，收购必须有足够现钱；买入价高于卖出价。出售同样受距离、落地、遮挡和药商知情拒绝交易约束。
- 自有止血药恢复25气血，干粮恢复10，气血初始60、上限100；满气血不消耗物品。当前没有战斗伤害或饥饿衰减。
- 靠近柳娘按 F 或按钮，消耗一份自有止血药救助。她会转向施救者；未蒙面时记住玩家，增加她对玩家的25点信任。蒙面时记住匿名善举，不生成具名信任或定向回礼。
- 救助20模拟秒后，柳娘根据施救时最后位置寻找恩人；再次看见并认出时更新位置，走到2米内才实际赠送15文。未加载、隔墙、找不到人或玩家再次蒙面时不会凭计时器自动付款。回礼从她初始40文的钱包扣除，只能发生一次。
- 药商只在自己确实知道未了结的拿取事件且能识别当前玩家时拒绝交易，不读取全知账本让所有商人知道。蒙面识别暂为简化二值模型。

## 数据与保存

新增 community.js：商品定义、背包容量、购买/使用/救助/回礼的数据转换及投影一致性校验。现有 firstLoop.js 记录新事件，并编排 NPC 的实际行动。场景适配器复用现有距离、遮挡、加载和角色移动接口；UI 展示库存、气血、受助者状态和信任。

progress.ledger.community 含 version=1、合法背包、商店库存、交易收入、柳娘回礼资金、气血、救助记忆和定向关系。主账本仍为version=1，新增可选社区子记录。无社区子记录的第一阶段旧档先按旧约束验证，再初始化该子记录并增加revision；不删除既有案件、物品、赔偿或历史事件。

保存校验从事件重新推导购买/消耗数量、库存、气血、资金与关系，只比较结果，不执行回礼或移动。钱的来源为玩家初始100文与柳娘40文，交易进入商店收入、赔偿进入赔偿记录；商品和回礼不是无限刷新。持有涉案药包时购买须留足20文赔偿，以免在当前无欠款系统时形成死局。

## 尚待统一验收

以下为待执行项目，未声称通过：买卖数量及资金守恒、满包/缺钱/缺货/满气血、合法药品与涉案药包分离、蒙面救助、延迟后实际接近回礼、离开加载区、回礼前后读档不重复付款、负面举报与救助同时发生时的行动优先级。

边界：仍为六名带名角色、两种合法消耗品、一件涉案物品和一次救助。通用装备、掉落/交易他人、完整NPC关系图、势力和悬赏尚未实现。第一阶段文档中的单格背包/只有负链是早期状态，当前以本补充为准。

## 出售与账本容量补充

新增 sell 事件和 community.tradeReceived 累计出售所得。旧社区记录缺少该字段时按0兼容，但若事件包含出售而投影遗漏收入，则校验拒绝。玩家余额为100－赔偿－购买支出＋出售所得＋已获回礼；商人现钱为60＋购买支出－出售所得。涉案药包不能出售。回放逐事件校验背包、商店库存与支付能力。

账本达到480条时停止新购买、出售、使用、救助和拿取，为正在进行的举报、交还、送回与回礼预留空间；不会因普通交易反复执行超过512条存档上限。仍待实际验收：买满后卖出再买、出售最后一件后连点、隔墙出售、具名纠纷时出售被拒、出售前后读档资金一致、旧社区记录兼容。
