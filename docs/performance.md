# 渲染与主线程性能

2026-09-08，基于 `core` 合并战斗系统后的 `cff65ad`。本轮仅做代码阅读、API 源码核对与修改，遵守 AGENTS.md，未运行测试、build 或 lint，也没有取得改动前后的实机 FPS。以下区分已实现的优化和后续候选，不能视作性能验收结果。

## 已发现并处理的开销

| 位置 | 原有开销 | 当前处理 |
| --- | --- | --- |
| GameCanvas | 高分屏默认最多 2 倍宽高渲染，即 4 倍像素 | 默认渲染精度 100%，可在图形配置中调整 50%–200%；菜单使用原有 CSS 分辨率 |
| 玩家、普通 NPC、货郎 | 大量独立 Mesh 表示衣物、肢体、竹篾和货筐，各自提交绘制 | 合并为每角色一个骨骼 Mesh，按材质合并连续子网格；每顶点一个骨骼权重，由 GPU 做蒙皮 |
| 静态建筑、自然物 | 已经使用普通 InstancedMesh，但仍参与矩阵/包围盒同步 | 冻结静态模板、实例和区块的世界矩阵，固定静态包围盒；保留实例化和动态视锥裁剪 |
| NPC 绕障 | 在渲染线程同步搜索最多 1,800 个网格节点 | 独立导航 Worker 搜索；主线程只同步碰撞区块增删和起终点 |
| Living HUD | 每帧发布状态；空命令队列也调用 Zustand set；每次渲染排序全部历史 | 常规发布约 10Hz，状态/忙碌/停机变化即时发布；空队列不更新；回顾仅在打开时按状态引用缓存 |
| NPC 绘制 | 重复深拷贝位置、设置装备颜色；未加载角色仍更新动画 | 原位复用位置快照，装备变化时才更新颜色/可见性；未加载角色跳过绘制更新 |
| 环境人群 | 反复进出视距时销毁并重建复杂货郎模型 | 当前最多 32 名环境 NPC 使用有界模型池，离开视距或未加载时禁用，退出世界时统一释放 |
| 区块流送 | 每帧扫描已加载区块的可见性与淘汰条件 | 只在跨区块或修改视距时扫描；地形 Worker 与分帧安装预算继续使用 |
| 场景鼠标输入 | Babylon 默认可能进行鼠标拾取查询 | 当前交互使用解析碰撞与朝向判定，关闭鼠标移动/按下/松开的场景拾取 |
| 静态纯色素材 | 一个模板有多个仅颜色不同的材质子网格 | 颜色烘焙到顶点，按单面/双面合批；保留城墙贴图和法线材质 |
| 碰撞查询 | 每次落脚、支撑、墙面/视线及寻路都遍历已加载碰撞体 | 主线程与 Worker 共用 8 米空间索引，只细查附近候选；区块安装/卸载时增删 |
| NPC 历史查询 | 每帧多次嵌套查找事实、目击、举报和犯罪记录 | 按不可变玩法快照构建索引，提交换状态时重建；识别、未报告/未受理证据、历史位置和装备查询复用 |

2 倍渲染精度调整到 1 倍时，像素数理论上减少 75%；这不是 FPS 提升比例。骨骼网格也不是每角色一次 draw call：材质子网格、单独显隐的武器、标签和玩家接触阴影仍需要绘制。

## GPU 骨骼接入

`src/game/assets/characters/createRigidSkin.js` 将原程序化角色零件合并，保留原 TransformNode 层级并通过 Bone.linkTransformNode 驱动骨骼。模型根变换只应用一次，合并后的顶点先回到模型坐标系，避免移动/缩放重复应用。

剑仍挂在原手臂节点，可独立装备/卸下；衣服继续使用原材质，装备颜色、受击闪色由原接口更新。给蒙皮网格及子网格设置覆盖挥击、货筐、披风和翻滚的保守包围盒，避免每帧在 CPU 上重算蒙皮顶点。此包围盒比精确轮廓大，会保守地多保留少量屏幕边缘绘制。

这次保留现有程序化动作，不增加外部模型依赖。每角色仍有独立骨骼和材质，因此没有把不同姿态角色强行放进同一个普通实例批次。

## 静态材质合批与碰撞索引

`createStaticMaterialBatches.js` 只接收资产注册器自己的纯色、不透明、无高光材质；已有顶点色、混合贴图或无法安全重排的素材保持原样。三角形和顶点坐标不变，将原颜色写入顶点，并把相同剔除方式的索引放在一起。可兼容的模板至多保留单面、双面两组，颜色不再逐个增加绘制批次。

Babylon 的默认顶点色在光照截断后相乘，与原 diffuseColor 的运算顺序不同。这里使用仅作用于上述纯色材质的 GLSL 插件，把颜色放回 diffuseColor，在强日照下保持原有计算顺序。没有修改引擎依赖或全局着色器。未来迁移 WebGPU 时需要补 WGSL 版本；当前游戏使用 WebGL Engine。

`collisionIndex.js` 将静态碰撞体登记到所有相交的 8 米格子中，涵盖旋转后的建筑、跨地形区块的模型以及屋檐外伸。查询范围同时考虑旋转矩形局部半径扩张，预计算 sin/cos，候选去重后执行原细查。索引随区块原子安装/淘汰，城墙独立常驻；未加载区域仍不可通行。屋顶支撑、贴墙轻功、移动和 Worker 寻路共用索引，碰撞不依赖材质或 GPU 合批结果。

NPC 状态索引只缓存由当前账本决定的事实。模拟时钟、距离、视线、追捕时效、招架释放与攻击扫掠仍每帧判断；不清空历史，不向其他 NPC 泄露未收到的证据，不改变提交/存档顺序。

## Worker 边界

`movementQuery.js` 是主线程与 Worker 共用的静态地面可通行规则，包括已加载区块、建筑/自然物、城墙、河道和桥栏。导航 Worker 不读取 Babylon 对象或 DOM，也不在每次请求中复制整张世界。

请求数限制为 8，设有超时与关闭清理。过期角色路线不会覆盖新请求，角色移动过远的结果会被丢弃。每一步仍由主线程检查当前碰撞、地面高度及角色身体，异步路线只提供候选路径。线程错误记录到开发日志及 runtime 统计；错误时不回退到主线程执行同一重搜索，角色仍可直行，绕障能力暂不可用。

较长的移动直线探测最多缓存 250ms，起终点移动超出阈值时失效；攻击扫掠、命中、目击、身份判断及实际落脚碰撞仍实时判定。玩家移动限制直接读取战斗模拟，避免依赖降频后的 HUD。

## 观察入口

Esc → 图形配置 → 显示帧率与性能，然后继续游戏。面板每 500ms 显示 FPS、帧间隔、场景 CPU、GPU、draw calls、活跃/总网格、网格遍历时间及实际渲染尺寸，关闭后停止采集。

新增模板材质批次的处理前/后计数，以及碰撞体数量和平均候选数。模板计数是已准备模板的子网格总数，不是当前帧 draw calls；候选/查询是本世界创建以来主线程的累计均值，不含 Worker 查询，遇到碰撞提前退出也计入查询。两者用于解释工作量，不替代实机 FPS 对比。

场景 CPU 仅计量 `scene.render()` 调用（包含场景更新回调），不包含浏览器全部工作、React 后续提交或等待刷新。GPU 使用 Babylon 的异步 GPU timer，显示最近完成的计时；不支持该扩展时明确显示缺失。CPU/GPU 有重叠，不能将两者相加视作完整帧耗时。开发环境同时写入 canvas 的 `data-performance`，不写存档、不上传数据。

## 后续候选，先由数据决定

| 数据表现 | 下一步 | 取舍 |
| --- | --- | --- |
| 活跃对象多、CPU 场景遍历高 | 静态自然物尝试按空间批次改 ThinInstance | 减少每实例 JS 对象；批次整体裁剪。当前普通实例跨区块共享模板，拆成许多小批次可能反而增加 draw calls |
| draw calls 仍高 | 进一步为带贴图材质制作纹理图集 | 纯色材质合批已实现；城墙法线贴图和透明材质需要独立处理 |
| 转身/远景 GPU 时间高 | 建筑、植被、货郎细节做 LOD，远处减少瓦垄/编织几何 | 骨骼合并不减少原模型三角形数量，仍需独立的几何层次设计 |
| 人群扩张到数百个角色 | 远处环境人群使用烘焙顶点/骨骼动画纹理 + 实例化 | 固定走路/站立循环适合烘焙；近处战斗、装备与轻功保留独立骨骼 |
| 玩久后 CPU 随历史变高 | 评估将账本 reducer/存档序列化放到 Worker | NPC 历史查询索引已实现；持久化迁移仍须保留单一权威、顺序、去重与 CAS |
| FPS 数值正常，但战斗动作像被暂停 | 测量每次动作等待 IndexedDB 的时间 | 当前逻辑在持久化确认前停止推进世界，这是事务设计造成的等待，单靠 GPU 或寻路 Worker 不能解决 |

暂未把整个引擎改为 WebGPU 或 OffscreenCanvas：当前代码中的提交数量、角色零件、UI 更新及寻路开销可以先独立消除，渲染后端迁移需要另行评估浏览器兼容性和输入/画布生命周期。

实现依据：[Babylon 骨骼文档](https://doc.babylonjs.com/features/featuresDeepDive/mesh/bonesSkeletons/)、[Babylon 实例化文档](https://doc.babylonjs.com/features/featuresDeepDive/mesh/copies/instances/)、[ThinInstance 的裁剪与开销](https://doc.babylonjs.com/features/featuresDeepDive/mesh/copies/thinInstances/)、[Worker 数据通信](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)。具体 API 同时核对了仓库安装的 Babylon 9.25.0 源码。
